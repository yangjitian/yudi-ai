# 项目说明文档：雨落有味·AI 美食顾问系统 (yudi-ai-backend)

## 1. 项目概述
- **项目名称**：雨落有味·AI 美食顾问系统 (yudi-ai-backend)
- **项目定位与目标**：本项目致力于打造一个温柔、专业且具备强执行力的 AI 智能辅助平台。通过聚合通义千问大模型能力、深度 RAG（检索增强生成）架构、并行工具调用机制及长文本解析能力，解决传统大语言模型应用中常见的“知识历史污染导致幻觉累积”、“串行工具调用响应迟缓”及“知识库与业务数据难以一体化协同”等痛点。适用于打造企业级特定领域知识问答助手、重依赖外部工具服务的私域 AI 助理场景。
- **整体一句话总结**：基于 Java 21、Spring Boot 3 与 Spring AI 生态深度构建，整合了彻底无污染 RAG 检索、SSE 流式打字机交互、MCP 标准化工具生态及大模型“深度思考”并发调度的现代化智能微服务系统。
- **项目类型**：前后端分离 / 智能体 (Agent) 架构 / 智能知识问答系统后端

## 3. 系统架构与设计
- **整体架构概览**：采用高内聚低耦合的四层职责分层架构
    - **表现层 (Access Layer)**：封装核心的 RESTful Web 路由及长连接 SSE 流式接口模块。负责拦截验证、流式心跳事件保活、手动打断请求捕获及统一标准异常捕获输出。
    - **业务支撑层 (Business Layer)**：处理包括会话拦截控制等常规核心功能流程，同时充当 AI 工作流水线的调度枢纽，把控用户在深浅 AI 对答模式间的逻辑切流。
    - **AI 领域控制层 (AI Core Layer)**：
        - **RAG 引擎**：负责意图消歧重写 (Query Rewriter) -> 向量检索召回 (Vector Retriever) -> 纯净上下文组装 (Context Refiner)。
        - **Agent 引擎**：依托深度思考范式 (Deep Thought, YdManus)，掌控 Function Calling 下的 ReAct 自闭环复杂迭代与多模并行任务。
    - **基础设施层 (Infrastructure Layer)**：采用 MySQL / PostgreSQL(PgVector) 双数据源架构；利用外接的 COS 存储并代理多来源跨类型的高质量知识资产摄入。
- **核心设计原则**：深度遵循 **Agent-Oriented Programming (面向智能体编程)**。坚持最小破坏原则：知识入模只作参考绝不破坏记忆主线。
- **典型设计模式与应用**：采用 **策略与工厂模式** 构建面向不同形态内容的 DocumentLoader 统一读取接口链；利用 **AOP 设计范式** 设计出高效的轻量权限检查验证器与 MyLoggerAdvisor 日志探针对切面监察体系。
- **系统安全与隔离机制**：
    - 使用 `@RequestHeader` 拉取 Authorization Token 并经由拦截器组装下沉入业务侧的 `UserHolder` 上下文保护舱，保证身份一致性并实时刷新长连接 TTL 生命周期防阻断。
    - 针对越权词汇 (如恶意破解 Prompt 防护墙) 的 Prompt Injection Audit，予以直接抛弃响应的自我脱胎能力。
- **鲁棒与异常重塑**：全局封装 `@ControllerAdvice` 搭建前后端友好错误交互码与信息结构体；遇到模型接口连接崩塌，自动接管完成兜底事件发射，维持业务体验的高可用感知。

## 4. 核心业务场景
### 4.1 场景一：无污染级标准 RAG 对话响应 (核心体验流)
- **业务价值 / 解决的问题**：彻底杜绝几千字乃至上万字长周期多回合 AI 探讨交流下，过时的海量检索阅读理解卡片对对话历史的长久“驻留污染”，极大减少 Token 大量重复计费和长上下文造成的“张冠李戴（幻觉）”。
- **完整交互流程**：
    1. 前端携带登录凭据，请求服务端生成并接收包含 `conversationId` 和实时分块消息的 SSE 发送通道。
    2. 后台捕捉真实 Query，针对高度精简语义不全指代词经过第一轮 LLM 的重写补全动作。
    3. `VectorStore` 根据最新意图下探至 PgVector，搜寻最邻近的高频置信度业务语料段。
    4. **(系统高亮)**：引擎进行防污染组装，将刚抓取的心得提取压缩成只在本单回合生效的 `SystemMessage`。同步通过“特征过滤拦截过滤网”，从原有的历史队列里擦除任何带有以往轮次系统旁白印记的问题和解释，保持绝对的“用户只讲原诉求，机器只留原响应”。
    5. 重组交付 DashScope 等引擎，结果利用 Reactive `Flux<String>` 推特级流式送达至前端。
- **支撑链路**：`ChatController` -> `Query Rewriter` -> 第二流 `JdbcTemplate` PostgreSQL 向量读取 -> LLM Provider -> SSE 长发推送。

### 4.2 场景二：YdManus 深度思考复杂任务链闭环 (高级 Agent 源码级深度剖析)
- **业务价值 / 解决的问题**：对齐近似 OpenAI o1 模型的逻辑梳理思考范式。传统 AI Agent 存在“无限死循环”、“串行分步调用导致响应极慢”以及“自作主张过度调用不需要的工具”三个致命缺陷。本项目通过在 `agent` 包下自研基类 `ToolCallAgent` 并衍生出强约束的 `YdManus` 实例，针对性提供并行的超级加速与高阶处理，彻底重塑大模型调用生态。
- **核心源码逻辑实现与交互流程**：
    1. **强约束的 Prompt 工程防“加戏”机制**：用户向 Agent 表达多元长命令后，进入由 `YdManus.java` 中硬编码的 `SYSTEM_PROMPT` 掌管的独立 ReAct 统摄链。明确指令模型“只有涉及必须获取的信息时才准调用工具，禁止主动推销（如‘需要我帮你生成PDF吗’）”。
    2. **底层架构剥离与自实现调度器**：核心基类 `ToolCallAgent.java` 通过 `.withInternalToolExecutionEnabled(false)` **彻底剥离并禁用了 Spring AI 默认的黑盒工具自动执行机制**。将解析、记忆上下文维护（`trimMemoryIfNeeded`）与核心执行方法 `act()` 流程完全收口自建。
    3. **多模并行 (Parallel Execution) 时空压缩**：当 LLM 解析出目标操作包含多个工具（如同时查寻商圈与搜图）时，注入的强制原则是 “Call them ALL AT ONCE in a SINGLE function call round”。随后交付自研控制器 (`ToolCallingManager`) 拦截，瞬间拉起 JDK 并发多线对不同端点执行**并行请求**，将串行拉网时间几何级压缩为单次最大网终耗时。
    4. **强制拦截与自我终结 (`doTerminate`)**：针对 ReAct Agent 常发的循环发散宕机灾难，YdManus 设计了强制伪工具节点。Prompt 规定完成必报 `doTerminate`。一旦调用发生，Java 代码层(`terminateToolCalled` 探测拦截逻辑) 予以直接打断并强制将其置于 `FINISHED` 状态剥离推理循环，确保交付 100% 确定性与安全。

### 4.3 场景三：业务语料文档智慧清洗与自动加载重投流
- **业务价值 / 解决的问题**：解决业务资料在热更、更迭淘汰下数据库知识陈旧的短板（冷启动延迟与错误历史知识），保证平台语料血脉永远为最新版本支撑。
- **完整交互流程**：
    1. 应用在系统部署冷启动期或接受手动更新触发任务。
    2. 探测对象资源变化。运用 Document API 进行加载分层与截断 (采用受限于模型单次向量 Embedding 的最佳批量配置，例如批处理上限 25)。
    3. `JdbcTemplate` 底层执行 Full Reload（全量重新写入）或采用增量检测策略对比。主动在主表检索并定向删除“文档物理消失但在向量维度中仍遗留”的孤儿向量碎片（Orphan Vec Clusters）。

## 5. 项目亮点与技术创新点
1. **彻底攻克 RAG 上下文污染难题 (The "Strict Filter" Momentary Context Paradigm)**：
   绝妙地创造了“瞬时上下文注入机制”。将检索出来的海量文献仅仅转换为当次 `SystemMessage` 的身份存在，模型运算一结束，数据库不会留存这部分引用文本作为下一轮的谈资参考。让每一句话都是“净度对放”，在保障参考可靠性的同时，砍掉 40%+ 的上下文消耗，扼杀越推越飘的幻觉积弊。
2. **“最小调用原则 + 并行函数执行”的双涡轮提速工具流**：
   抛弃内置平庸的方法链，构建私有 `YdManus` 系统并注入“必须最小并发”的思想指令。在处理复杂网络 IO （诸如找餐馆找天气并发抓取图片）时进行系统切面拦截并发多开协程任务并重汇组装。这令 Agent 执行力相比传统排队问询至少产生了 3 倍以上可观的执行降阻性能飙升。而且配合闭环 `doTerminate` 掐断反馈完美阻挡了 Agent 由于多言迷失陷入循环风暴可能。
3. **前沿化打字机式长推交互引擎 SSE与强容错体系**：
   区别于普通 WebSocket 与简单 Ajax，项目选用 Server-Sent Events 流式协议。不但单向极度轻量，更完整构筑了（心跳事件防挂断、客户端可发起 /pause 指令暂停回显、错误捕获自发替代）等全生命周期多分支管理流程，为用户层带来了极其顺畅有生命感的打字反馈表现。
4. **统一抽象化的 MCP 生态服务总线纳管方案**：
   架构超前性地应用了模型上下文协议 (Model Context Protocol, MCP)，剥离原本堆砌的复杂 SDK 逻辑。以标准化协定直接在基础设施层代理连接提供外部算例（如高德地图工具服务器），真正让系统的能力突破内网壁垒变成了一个具有可拔插模块生态概念的可生长智能生命。
5. **高度工程化与降本增效的 PostgreSQL 向量/业务同栖双塔架构**：
   突破行业通常强加分离 Vector 向量独立数据库带来的繁荣维护压力。在此引入原生具备强一致性的 PG HNSW/Cosine 能力，实现业务数据关联同驻一台结构服务器中稳定高速穿梭，同时搭配另一MySQL处理一般级业务查询，分库分工。
6. **精致入微的对话 Query 小模型前瞻梳理预处理机制**：
   增加独立的前置化意图“消歧提取”（Query Rewriter 预运算缓存支持），对简短且口语指代重叠强烈的口语问询施以修正重塑，让后面深探入库检索时准度跃升好几等层级。

## 6. 潜在优化方向与建议
1. **全面完善测试链路及 CI / CD 工作流建设**：
   - *问题：* 目前工程主要重于核心链路开创落地，单元测试覆盖相对不足。
   - *建议：* 引入 JUnit / MockMvc 构建包含 RAG 查询链、并行 Tool Calling 与 SSE 事件流解析的全场景系统级联调单元测试群；配置如 GitHub Actions / Jenkins 等完成全自动化 CI 构建。
   - *收益：* 为后期的多端联发提供钢铁版的底层修改不破损工程防浪堤。
2. **构建平台级可观测立体大屏 (Observability Dashboard)**：
   - *问题：* 缺乏量化的性能耗散面板统筹。
   - *建议：* 结合 Micrometer 接口并对接 Prometheus 与 Grafana。构建展示 (P95 / P99 响应耗时 / 大模型 Token 单日与高峰流经开支量统计 / RAG 各环节命中率与并发耗费时移) 系统展板。
   - *收益：* 让隐秘于服务器内部的模型开销消耗不再像瞎子摸象一样，真正变成可用指标化指导财务和算力优化的工具指盘表。
3. **架构级的配置敏感数据安全漂移 (Secret Management)**：
   - *问题：* 当拥有大量跨供应商密钥和内网穿透授权。
   - *建议：* 脱离代码化配置理念。建议抽离如阿里云大模型密钥与服务器网段库鉴权相关关键口令至专用 Vault 服务（乃至集成各大公有云企业级的 Key Management Service (KMS) 中去强控取用生命周期）。
   - *收益：* 不论在应对任何级别的安全攻防代码审查以及防商业秘钥大面积泄露的情景中都游刃有余。
4. **升维复杂文档拆解颗粒度 (如采用智能切块)**：
   - *问题：* 长文档仅凭借基础算法分段很难真正做到针对复杂混写文案表单内（比如配方表格、流程树干图表等）完美解析。
   - *建议：* 可考虑引入小型的文本结构感知或甚至图像解析类模型 (VLM) 在进行初次库容增量消化时先走一遍基于结构语义树感知的 Semantic Splitter （语义切解）。
   - *收益：* 对极其专业的深度指南等垂直资料进行更加具有“人眼结构识别提取”的反馈，检索准度向天花板级别更逼近一步。
